## 1. 背景：现有侧栏的三个问题

现状：右侧 340px 单列侧栏，自上而下依次为「错误条 → 当前回合 → 操作提示条 → 移动魔典 → 魔法药水 → 法术符文 → 结束回合 → 说明脚注」。实测（`three.css` 与 1440×900 视口）：

| 问题 | 实测数据 | 后果 |
| --- | --- | --- |
| 字号过小 | 说明正文 7.5px、元信息 7px、卡牌主字 10px、面板标题 11px | 长时间阅读疲劳，7.5px 属于必须眯眼的区间 |
| 信息重复三遍 | 轮次/阶段/当前玩家同时出现在 `location-plaque`、`turn-panel`、`PlayerPanel`；满瓶数出现在 3 处 | 侧栏臃肿，删掉不丢信息 |
| 操作方向割裂 | 提示条 `IntentBanner` 位于侧栏内、手牌**上方**（`ThreeGameContainer.tsx:548`），而点击发生在下方手牌 | 视线要向上回跳，「下一步」与「刚点的东西」在空间上分离 |
| 空间告急 | 侧栏内容约 780px，可用高度约 830px；窗口高 < 860px 时第 4 个法术需滚动 | 法术区已被压缩到临界 |

结论：**问题的本质不是侧栏太窄，而是把 Z 轴的信息压到了 X 轴上。**

---

## 2. 设计原则

1. **用纵深表达层级，而不是用平面腾挪。** 近＝当前操作对象，远＝备选资源，最远＝场景本体。
2. **常驻状态沉入背景。** 轮次、玩家、药水、地点等信息贴舞台四角，做成"悬浮在 3D 空间里"的羊皮纸薄片，不占用可操作面积。
3. **下一步永远长在当前对象的正下方。** 点了哪张牌，下一步就在那张牌下方，视线只向下走，不回跳。
4. **一次只有一个"主卡"。** 金色符文环只给被选中或被悬停的那一张，避免多点高亮造成噪音。
5. **规则引擎零改动。** 本方案只替换表现层与拾取层，`@wt/engine` 一行不动。

## 3. 空间分层（Z 轴）

以相机为原点、屏幕法线为 Z 轴，共 5 层：

| 层 | 内容 | 深度（世界单位，原型取值） | 表现 |
| --- | --- | --- | --- |
| L0 场景层 | 棋盘、塔、鸦堡、巫师、植被、云雾 | 场景本体，约 1500–2100 | Three.js 实体几何 + PBR 材质 |
| L1 常驻 HUD | 地点铭牌、步骤提示、回合面板、药水统计、结束回合 | 屏幕四角（DOM） | 羊皮纸薄片 + 鼠标视差，不拦截棋盘点击 |
| L2 资源层 | 法术牌堆（4 张） | dist ≈ 1500，缩放 0.62 | 缩小、偏转、压暗，表达"在远处堆叠" |
| L3 手牌层 | 3 张手牌扇形 | dist ≈ 1170–1230，缩放 0.90 | 完整亮度，悬停上浮 |
| L4 主卡层 | 被选中的卡牌 | dist ≈ 950，缩放 1.10 | 推进放大，后方浮现双层魔法阵 |
| L5 交互层 | 移动巫师 / 移动塔 / 骰子 | 贴着主卡下缘（DOM） | 羊皮纸浮层，随主卡投影定位 |

> 深度值不是美术随意取值，而是由 **NDC 定位 + 距离** 反解出的世界坐标：卡牌永远落在画面指定位置，换分辨率不会飞出视口。

## 4. 交互流程

### 4.1 出牌三步（向下推进）

```
[手牌 3 张] --点击--> [主卡抬升 + 魔法阵展开]
                          └─ 正下方浮层：第 1 步「移动巫师 / 移动塔」
                                └─ 选完 → 第 2 步「掷骰」
                                      └─ 掷出 → 第 3 步「点击场上目标」
```

- 第 1 步未完成前，其余两张手牌退到后方并压暗（opacity 0.14–0.20），保留"还能改选"的暗示。
- 第 2 步的骰子与第 1 步的两个按钮在**同一浮层内向下生长**，不新开窗口。
- 第 3 步的提示交给舞台顶部固定条 + 场上目标光圈，避免浮层遮住棋盘。

### 4.2 法术牌堆 ↔ 手牌 交换

| 触发 | 表现 |
| --- | --- |
| 鼠标进入左后方牌堆 | 4 张符文卡沿路径飞至前景展开；同时 3 张手牌沿**相反路径**退到牌堆位置并收成一摞 |
| 鼠标在展开区 | 保持展开 |
| 鼠标离开 0.55s | 反向播放，各归其位 |
| 点击某张符文卡 | 该卡迸发青色粒子，顶部提示条显示该法术的规则与代价 |

交换是"取用即换位"的隐喻：桌面上同一时刻只有一副牌在前面。

### 4.3 法术提示的分级

| 场景 | 位置 | 文案规格 |
| --- | --- | --- |
| 移动巫师 / 移动塔 | 舞台顶部固定条 | 一句话，含步数与目标类型 |
| 交换双塔 | 同上 | 分两步提示「第一个塔堆」→「第二个塔堆」 |
| **解封巫师** | 固定条 + 浮层内一行警示 | 「消耗 1 瓶满药水 · 若该塔内没有你的巫师，**药水依然消耗**」 |
| 药水不足 / 次数用尽 | 符文自身禁用态 | 去饱和 + 悬停说明原因，不做上浮 |

## 6. 技术方案

### 6.1 卡牌：从 DOM 按钮改为 3D 平面

| 项 | 现状（DOM） | 方案（3D） |
| --- | --- | --- |
| 载体 | `<button class="book-card">`，6 层 CSS 3D 结构 | `PlaneGeometry` + `CanvasTexture`（512×760） |
| 文字 | 真实 DOM 文本，可选中、可无障碍读屏 | canvas 绘制，`text` 不可选中、无读屏语义 |
| 拾取 | 原生 click | `Raycaster` + 手动命中盒 |
| 层级 | z-index + preserve-3d | 真实 Z 深度，天然遮挡与透视 |

**取舍**：换取真实透视与景深，代价是无障碍与文本选择能力，需要单独的降级方案（见 §8）。

### 6.2 定位：NDC 槽位 + 平滑相机

```js
// 槽位只记 (nx, ny, dist)，每帧反解世界坐标
_v.set(slot.nx, slot.ny, 0.5).unproject(smoothCam).sub(smoothCam.position).normalize();
card.position.copy(smoothCam.position).addScaledVector(_v, slot.dist);
```

- `smoothCam` 是对真实相机做 lerp 的副本（约 150ms 延迟）→ 相机转动时卡牌略有滞后，产生**视差**，强化"牌飘在面前"的感觉。
- 朝向 = 相机朝向 + 桌面倾斜角（`tilt`）→ 既有正对可读性，又不完全贴脸。

### 6.3 交互浮层：DOM 跟随投影

3D 元素在近景时，屏幕坐标是强非线性的：卡牌下移 150 世界单位，视角变化可达 30°，浮层极易飞出视锥。因此第 5 层用 DOM：

```js
const screenH = (CARD_H * slot.s) / worldPerPx;       // 卡牌在屏幕上的高度
popover.style.top = cardScreenY + screenH * 0.52 + 10; // 卡牌下缘再给 10px 间距
```

浮层永远在画面内（左右/上下夹取），文字始终锐利，且可覆盖键盘与读屏（见 §8）。

### 6.4 与规则引擎的接口

零改动。仍走现有 `UIIntent` 状态机：

| UIIntent | 对应本方案的层 |
| --- | --- |
| `IDLE` | L3 手牌可点 |
| `PLAY_CARD_MODE_CHOICE` | L5 浮层第 1 步 |
| `PLAY_CARD_DICE` | L5 浮层第 2 步 |
| `PLAY_CARD_WIZARD` / `TOWER_PICK` | L4 主卡 + 顶部固定条 |
| `CAST_SPELL_*` | L2 展开后的符文卡 + 顶部固定条 |

## 8. 风险与边界

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 无障碍退化 | 3D 卡面无 DOM 语义，键盘不可达、读屏不可读 | 保留一层视觉隐藏的 DOM 按钮镜像，与 3D 命中同步 |
| 移动端 | 窄屏下 NDC 槽位重叠，浮层易顶到边缘 | `aspect < 0.9` 时降级为底部横向卡带 + DOM 手牌（不启用 3D 卡面） |
| 文字锐利度 | CanvasTexture 在缩放时可能发虚 | 卡面画布 512×760，`anisotropy=4`；DPR 上限 2 |
| 性能 | 粒子 + 阴影 + 透明卡面叠加 | 粒子池上限 900；阴影贴图 1024；移动端关闭阴影 |
| 拾取冲突 | 拖拽旋转与点击卡牌共用 pointer | 位移阈值 > 6px 判定为拖拽，不触发点击 |

### 9.2 与设计的偏差（有意为之）

| 项 | 设计 | 实际 | 原因 |
| --- | --- | --- | --- |
| 渲染通道 | 与棋盘同一 WebGL 场景 | **独立透明画布**（`.card-layer-canvas`，z-index 4） | 舞台的 `.stage-mist` / `.stage-vignette` 会冲淡卡面，独立图层可保证卡牌恒定清晰；同时天然压过雾气、低于 HUD |
| 侧栏 | P3 才删 | 现在只移除「移动魔典 / 法术符文」两块 | 玩家面板、药水、结束回合仍需要落位设计，先保留可玩性 |
| 色调映射 | 跟随场景 ACES 0.78 | 卡牌层 `NoToneMapping` + `toneMapped:false` | 卡面是 UI 资产，应逐像素还原绘制结果，不应被场景曝光改变 |
| 槽位尺度 | 原型世界单位 | 按真实场景缩放（卡高 2.49，手牌距相机 15.4） | 真实棋盘半径约 8.5，相机距离约 30 |

### 9.6 魔法瓶（3D 漂浮）

- 位置随右上状态卡下方排布：NDC `nx = 0.56 → 0.94`，`ny = 0.45`，距相机 14.2，瓶高 1.17 世界单位。
- 卡面 240×400 画布绘制：`FULL` 有液面椭圆、液体渐变、气泡与高光；`EMPTY` 仅玻璃轮廓与底部残液；`SPENT` 木塞歪斜 + 裂纹。
- 玻璃体使用「边缘不透明、中心通透」的横向渐变，因此空瓶会透出背后的场景，满瓶能看到液体折射感。
- 轻微上下浮动与旋转（振幅 0.008 NDC / 0.04 rad），与手牌一致保持"漂浮"语汇。

### 9.7 骰点锁定规则（2026-11-24 修订）

出牌流程加入「骰点即锁」约束，修复了「取消后重新点牌可重掷」的漏洞：

| 动作 | 行为 |
| --- | --- |
| 掷骰 | 点数写入 `lockedRollRef: Map<CardID, {value, mode}>`，意图进入 `locked: true` |
| 再次点击同一张牌 | 直接恢复该点数与锁定态，**不重掷**，并给出锁定提示 |
| 点击其他牌 | 拒绝，提示「当前有一张牌已掷骰锁定，请先完成本次移动或直接打出」 |
| 结束回合 | 拒绝，同样提示先完成当前出牌 |
| 命中合法目标 | 正常结算，成功后释放锁定 |
| 无合法目标 / 想放弃 | 「直接打出（放弃移动）」按钮常驻于锁定态；内部传一个必然无效的目标 id，引擎按 V2 §20.1「非法目标 → 行动消耗」处理，**不改规则也能保证任何局面可走完** |
| 取消按钮 | 锁定后不再出现，替换为上述「直接打出」 |

> 引擎侧 `resolveMoveValue` 本就优先采用客户端传入的 `resolvedMoveValue`，因此锁定逻辑完全在 UI 层，规则与引擎零改动。

### 9.8 魔法瓶造型（2026-11-24 修订）

按「魔药药剂瓶」而非试管重绘：细颈 + 圆肚瓶身 + 软木塞 + 封蜡。

- 画布 240×400，瓶身贝塞尔曲线（最宽 128px），颈宽 46px。
- `FULL`：液体渐变 + 液面椭圆 + 16 颗气泡 + 底部沉色 + 左侧竖向高光 + 肩部环形反光。
- `EMPTY`：仅玻璃轮廓与底部残液，玻璃用「边缘实、中心透」的横向渐变，可透出背后场景。
- `SPENT`：木塞歪斜 0.4rad、瓶身裂纹、封蜡去饱和。
- 尺寸缩小：平面 0.54×0.9，间距 0.058 NDC，右对齐排在 `nx 0.625 → 0.94`。

### 9.9 命中区域：只有卡面可点（2026-11-24 修订）

问题：`pick()` 原先用 `intersectObjects(roots, true)` 递归整个卡牌组，魔法阵平面（`CARD_W×1.72`、`CARD_H×1.58`）
也被算作可命中对象。由于它比卡面大一圈，**光效覆盖的矩形区域会抢走指针**：悬停到光效上卡牌就浮起，
点击光效区域时也只会命中卡牌，导致点到后面的巫师/塔没有反应。

修法（两层保险）：

| 层 | 做法 |
| --- | --- |
| 装饰对象 | `aura.raycast = () => {}`、`auraGold.raycast = () => {}`，从源头退出射线检测 |
| 命中集合 | `pick()` 只对 `runtime.face` 求交（`recursive = false`），不再遍历整组 |

语义：**卡牌的有效区域 = 卡面矩形本身**；魔法阵、光晕、粒子只做视觉，不参与任何命中与悬停判定。
`opacity ≤ 0.5` 的卡（如法术展开时收起的手牌）仍不参与命中。

### 9.10 选目标态：主卡让位（2026-11-24 修订）

进入「选巫师 / 选塔」后，玩家要点的目标在棋盘上，而主卡此时正压在棋盘中央 —— 遮住了最常点的区域。
这一步把主卡退开：

| 项 | 选模式 / 掷骰态 | 选目标态 |
| --- | --- | --- |
| 主卡位置 | 屏幕中央（`0, -0.10`） | **左下（`-0.50, -0.54`）** |
| 主卡缩放 | 1.12 | **0.78** |
| 提示浮层 | 卡牌正下方居中 | **卡牌右侧，垂直居中**，箭头朝左 |
| 其余手牌 | `HAND_OUT`（底部、压暗 0.14–0.22） | `TARGET_OUT`（左右下角、压暗 0.18–0.26） |
| 棋盘中部 | 被主卡覆盖 | **完全露出** |

实现要点：

- `CardLayer` 新增 `TARGET_SLOT` / `TARGET_OUT_SLOTS` 与 `targetingId`；`setData()` 多一个参数，由 `ThreeGameContainer` 传入。
- `targetingCardId` 只在 `PLAY_CARD_WIZARD` / `PLAY_CARD_TOWER_PICK` 两个意图下非空 —— 选模式、掷骰阶段仍用中央大卡（那时不需要点棋盘）。
- 浮层通过 `.card-popover.is-side` 换位：`left = 卡右缘 + 18px`、`top = 卡中心 − 浮层高/2`，箭头从「上」改为「左」。
- 两处都有边界钳制，窄窗口时自动收回舞台内，不会出画。
